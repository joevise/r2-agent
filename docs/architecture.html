01设计哲学：三条公理

R2 的每一行代码都必须能映射到这三条公理——映射不上的代码不存在。
公理含义活案例
内核产生能力，壳做观察与交互能力=模型能调用的工具；一切展示/编排都在壳层技能系统：内核零改动，只是 prompt 注入 + 文件扫描
先用法后造法没有真实使用场景的功能不写；bash 能解决的先不造专用原语子 Agent 孵化：bash 自孵化验证够用后，spawn 原语搁置
诚实降级环境受限时 warn + 降级，绝不静默失败沙箱三级降级链；GLM 审查掐流显式报错（v0.5.3）

能力边界的推导

Agent 需要什么能力？——读写文件、执行命令、跨会话记忆、被嵌入。除此之外的一切（MCP、技能、Console）都是这四件事的组合或包装，都在壳层：

  • skill 不需要框架：技能 = 磁盘上的 SKILL.md 文件 + agent 的 read/bash。动态扫描注入 prompt（v0.6.0），装了就会用，内核 0 行改动
  • MCP 是生态适配器：不是新能力，是"借别人能力"的标准接口，住在壳层配置里
  • 沙箱是使用许可：能力不变，改变的是能力的边界

关键设计点

  • 思考流与正文分离：GLM 的 reasoning_content 单独解析成 Thinking 事件——思考 token 计入用量（计费诚实），不进正文，不入会话历史
  • steer 不等回合结束：tokio::select! 同时监听模型流和转向通道，转向即时生效（当前流被抛弃，上下文保留）
  • 崩溃恢复零丢失：每条消息即时 fs 到 JSONL，kill -9 后 recover() 逐行重放（实测验证）

双 fork 进程树（v0.5.2）——沙箱最精妙的一段

flowchart TB R2["r2 主进程"] --> MID["中间进程（保姆）
unshare(user? + mount/pid/net ns)
MS_PRIVATE 锁挂载传播
bind work → 最小根/work"] MID --> SUN["孙进程 = 新 PID ns 内的 PID 1
挂 /proc（只含沙箱进程）
chroot 最小根 + chdir(/work)
execve sh -c 命令"] MID -.->|waitpid 传播退出码
（信号→128+sig）| SUN SUN -.->|PID 1 死亡 → 内核回收
整个进程空间·零僵尸| X["💀"]

为什么必须双 fork：unshare(CLONE_NEWPID) 只对之后 fork 的子进程生效。单 fork 时挂 /proc 会暴露宿主进程列表，/proc/1/root 更是经典 chroot 逃逸面——v0.5.0 实测发现后禁挂 /proc，v0.5.2 双 fork 彻底解决：孙进程"出生"在新 PID 空间，由它挂的 /proc 天然只见沙箱自身。

06上下文管理：L1 / L2 / L3

层对象机制持久化
L1当前上下文窗口token 预算监控（模型注册表自动推导窗口）—
L2会话内压缩超阈值时旧消息交摘要模型折叠成 system 摘要，近期消息保留会话 JSONL
L3跨会话记忆智谱 embedding-3（2048 维）语义检索 + 时间衰减打分，新会话自动召回相关记忆SQLite memory.db
L3 是对 Pi/MCP 生态的差异化武器：别的 Agent 重启即失忆，R2 记得上次装的 MCP、上次聊的决策。检索是语义级的（embedding 相似度），不是关键词匹配——问法变了也能召回。

  • 追加式 JSONL：每条消息一行（type/role/content/ts），永不重写，崩溃后逐行重放即恢复
  • SessionTree：分叉只存父引用+upto 断点，共享前缀零拷贝；循环引用防御（visited set）+ 断链降级
  • Console 的切换/回放：resume 时按父链拼出完整历史（v0.5.4），UI 回放含工具块还原

自孵化 vs Docker（方向修正案例）：原计划每会话一个 Docker 容器。后来想通——Docker 的隔离本体就是 namespace+cgroup+seccomp，这三个内核原语 R2 已全部自实现。自孵化方案每会话开销 15-25MB（纯进程）vs Docker 40-60MB（shim+容器），启动 <100ms vs 1-2s，零外部依赖。隔离强度相同，泄漏点更少。这是"不能映射到公理的代码不存在"的架构级应用。

  • 技能闭环：装了就会用（v0.6.0 实测：agent 第一动作就是 cat SKILL.md）；技能教 agent 装 skill（writing-skills 技能自己就在技能目录里）——自举
  • MCP 闭环：对话中说"帮我装个 tavily"→ agent 调 mcp 工具写配置 → 新会话自动连接（文本手术写入，保注释/字段序）
  • 边界清晰：技能=自有知识（文件+prompt 注入）；MCP=外部能力（进程+协议）。都不在内核

10模型层：双 Provider + 注册表

  • openai_compat：GLM-5.2 等（SSE 流式，reasoning_content 思考流解析）；anthropic：Kimi coding plan 等——两家真实跑通，切换只改 config
  • models 注册表（38 模型）：上下文窗口自动预算（未知模型 128K 兜底）、输入/输出参考价（国际走 OpenRouter 实时 API，国内走官方定价）、coding plan 标注——成本核算有据可依
  • 建连重试：429/5xx 指数退避（1s/2s/4s），流开始后不重试（幂等性诚实）
