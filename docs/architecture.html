01设计哲学：三条公理

R2 的每一行代码都必须能映射到这三条公理——映射不上的代码不存在。
公理含义活案例
内核产生能力，壳做观察与交互能力=模型能调用的工具；一切展示/编排都在壳层技能系统：内核零改动，只是 prompt 注入 + 文件扫描
先用法后造法没有真实使用场景的功能不写；bash 能解决的先不造专用原语子 Agent 孵化：bash 自孵化验证够用后，spawn 原语搁置
诚实降级环境受限时 warn + 降级，绝不静默失败沙箱三级降级链；GLM 审查掐流显式报错（v0.5.3）

能力边界的推导

Agent 需要什么能力？——读写文件、执行命令、跨会话记忆、被嵌入。其余一切（MCP、技能、Console）都是这四件事的组合或包装，都在壳层：

  • skill 不需要框架：技能 = SKILL.md 文件 + read/bash。动态扫描注入 prompt（v0.6.0），内核 0 行改动
  • MCP 是生态适配器：借别人能力的标准接口，住在壳层配置
  • 沙箱是使用许可：能力不变，改变的是能力的边界

05三级沙箱：从防误操作到结构性隔离

level = off无隔离
（本机信任环境）
level = container（默认）rlimits（CPU/AS/FSIZE/NPROC）
环境变量清洗（白名单+PATH重设）
cgroup v2 pids（fork炸弹内核级拦截）
高危命令启发式（可选·防误操作）
level = strictcontainer 全部 +
mount ns：chroot busybox 最小根（宿主路径不存在）
pid ns：双fork（/proc 只见沙箱自己）
net ns：断网（反弹 shell 不可能）

降级链（诚实原则的活用）

strict 请求
▼can_namespace()() 探测：root 或 AppArmor 未限制？
否 → warn 降级 container
（Ubuntu 24.04 空壳 userns：unshare 成功但 uid_map EPERM——实测发现）
是 → 尝试双 fork namespace
▼unshare 被 EPERM 拦？（容器 seccomp）
是 → warn 摘除 ns 重试（降级 container）
▼cgroup 可用？
否 → warn 降级 rlimits
✓ 全部生效

双 fork 进程树（v0.5.2）——沙箱最精妙的一段

r2 主进程
▼ fork
中间进程（保姆）unshare(user? + mount/pid/net 三件套)
MS_PRIVATE 锁挂载传播（防回传宿主）
bind work_dir → 最小根/work
▼ fork（关键：孙进程"出生"在新 PID 空间 = 其中的 PID 1）
孙进程挂 /proc（挂载者在新 ns → 只含沙箱进程，宿主结构性不可见）
chroot 最小根 + chdir(/work) + execve sh -c 命令
⇄ waitpid 传播退出码（信号→128+sig）PID 1 死亡 → 内核回收整个进程空间 · 零僵尸

为什么必须双 fork：unshare(CLONE_NEWPID) 只对之后 fork 的子进程生效。单 fork 时挂 /proc 会暴露宿主进程列表，/proc/1/root 更是经典 chroot 逃逸面——v0.5.0 实测发现后禁挂 /proc，v0.5.2 双 fork 彻底解决。

06上下文管理：L1 / L2 / L3

层对象机制持久化
L1当前上下文窗口token 预算监控（模型注册表自动推导窗口，未知模型 128K 兜底）—
L2会话内压缩超阈值时旧消息交摘要模型折叠成 system 摘要，近期消息保留会话 JSONL
L3跨会话记忆智谱 embedding-3（2048维）语义检索 + 时间衰减打分，新会话自动召回SQLite memory.db
L3 是差异化武器：别的 Agent 重启即失忆，R2 记得上次装的 MCP、上次聊的决策。检索是语义级的（embedding 相似度）——问法变了也能召回。

07会话持久化：JSONL 追加 + 分支树

sess-A.jsonluser → assistant → tool → … （每条一行，永不重写）
↙ fork(parent=A, upto=5)
↘ fork(parent=A, upto=3)
sess-B.jsonlbranch_from: A, upto: 5
恢复 A 前 5 条，独立追加
sess-C.jsonlbranch_from: A, upto: 3
  • 追加式 JSONL：崩溃后逐行重放即恢复（kill -9 实测）
  • SessionTree：分叉只存父引用+断点，共享前缀零拷贝；循环引用防御 + 断链降级
  • Console 切换/回放：resume 按父链拼完整历史（v0.5.4），UI 回放含工具块还原

自孵化 vs Docker（方向修正案例）：原计划每会话一个 Docker 容器。后来想通——Docker 的隔离本体就是 namespace+cgroup+seccomp，这三个内核原语 R2 已全部自实现。自孵化：每会话 15-25MB（纯进程）vs Docker 40-60MB（shim+容器）；启动 <100ms vs 1-2s；零外部依赖；隔离强度相同，泄漏点更少。这是"不能映射到公理的代码不存在"的架构级应用。

技能系统（自有 · 零框架）

↓ 会话启动动态扫描
↓ 清单+使用约定注入 system prompt
↓ agent: cat 读全文 → 遵循执行
↓ 装新 skill 也写该目录（自举闭环）
MCP（生态适配器）
config.toml [[mcp.servers]]
↓ 启动时 stdio 握手列出工具
↓ mcp_{name}_{tool} 像内置工具调用
↓ 内置 mcp 工具 add/list/remove
↓ 对话中"装个tavily"→写配置→新会话生效
  • 技能闭环：装了就会用（实测：agent 第一动作就是 cat SKILL.md）；writing-skills 技能教 agent 写技能——自举
  • 边界清晰：技能=自有知识（文件+prompt）；MCP=外部能力（进程+协议）。都不在内核
